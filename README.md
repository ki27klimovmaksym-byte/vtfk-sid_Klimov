# `vtfk-sid` — ядро С.І.Д.

Це **твій** репозиторій на весь семестр. Створюється один раз, у ЛР1, і живе до ЛР10.

Він не той самий, що репозиторій завдання. У тебе їх два, і в кожного одна робота:

| Репозиторій | Що там | Як здається |
|---|---|---|
| репо завдання (`sp-<група>-labNN-<логін>`) | **рівень 1** + `REPORT.md` | тегом `submit/labNN`, перевіряють автотести |
| **цей** (`vtfk-sid`) | **ядро**: рівні 2 і 3 усіх десяти місій | показуєш на занятті, оцінює викладач |

Рівень 1 щоразу самодостатній: пропущене заняття його не блокує — приходиш і здаєш «3» без
перешкод.
Ядро — інша історія: воно росте, і кожна ніч додає до нього шар.

## Що де лежить

```
core/
  capsule/      Docker-капсула С.І.Д.
    Dockerfile          багатоетапний, фінальний          (ніч 2)
    Dockerfile.naive    «танк» для порівняння розмірів    (ніч 2)
    deploy.sh           ідемпотентне розгортання          (ніч 1)
  sid/          заготовка ядра → справжній crate           (ніч 2 → ніч 4)
  sidkit/       Rust-crate: інструменти С.І.Д.             (ночі 4–7)
    src/logscan.rs      читання чужих логів                (ніч 5)
    src/guard.rs        стани ворожих вузлів               (ніч 6)
    src/intel.rs        стійке читання, що не падає        (ніч 7)
  wasm/         WAT-проби і фінальне ядро                  (ночі 8 → 10)
    probe.wat           перша власна інструкція            (ніч 8)
    compare/            той самий алгоритм у двох АСМ      (ніч 9)
```

Порожні теки з `.gitkeep` — це не сміття, а карта: до кінця курсу заповниться кожна.

## Що робити, якщо ніч пропущена

Візьми знімок ядра з окремого репозиторію — по гілці на ніч:

```bash
git clone -b after-lab04 git@github.com:AlexOrd/vtfk-sid-reference.git vtfk-sid
```

Знімок — це **робочий стан, а не розв'язок**: у ньому лише те, що дає рівень 1 попередньої
ночі. Сюжетно це С.І.Д. передає копію: «я зберіг знімок тієї ночі, візьми його».

Оцінка за версію «на референсі» **така сама**, як за версію «на своєму ядрі». Різниця не в
складності, а в тому, звідки взято вхідні дані.

## Здача

Цей репозиторій **не** здається тегом. Його ти показуєш на захисті: відкриваєш, запускаєш,
розповідаєш, чому це працює. Оцінку «4» і «5» дає розмова, а не наявність файлів.

Це не формальність, а прямий наслідок того, що репозиторії завдань публічні: списаний код
нічого не дає, бо оцінюється не він.
